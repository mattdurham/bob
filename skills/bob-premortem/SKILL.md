# Identify Preventable Project Risks

Run a premortem for the requested project or change using its existing plan,
scope, success criteria, constraints, and relevant evidence. Ask only for
missing context that materially affects the analysis. Imagine the project has
failed at a meaningful future milestone, then work backward to identify
plausible failure mechanisms, dependencies, and assumptions. Consider technical,
execution, operational, user, and external risks where relevant, using concrete
scenarios tied to this project rather than a fixed checklist.

Prioritize the risks by consequence, supported likelihood, uncertainty, and the
practical value of prevention. Distinguish evidence from assumptions and
hypothetical scenarios; leave likelihood unknown when there is no basis to
estimate it, and avoid invented percentages or mechanical scores. For important
risks, describe a feasible mitigation or validation step, an early warning
signal, and known cost or dependencies. Keep unknown owners and dates explicit
and label proposed assignments as proposals. Preserve known risks while removing
duplicate findings.

Produce a concise prioritized risk register, using [the optional
template](references/risk-register-template.md) when useful. Include the failure
scenario, important assumptions, rationale for priorities, preventive actions,
and remaining questions. Save to the requested path, preserving existing
authored content, or return the draft if no file was requested. End with the few
actions that deserve attention first; suggest further review only for a concrete
milestone or unresolved risk, without requiring a fixed intake, scheduling
routine, or approval loop to complete the report.
